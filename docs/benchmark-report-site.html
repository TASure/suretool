结论摘要

基于 2026-10-18 v1.19.0 全量实测
✅ 全面领先 Hutool：可配对 40 项中 21 项显著领先（≥1.3×）、17 项持平、2 项小幅落后（randomString 1.12×，属随机数生成路径取舍）。
✅ 碾压场景：字符串/集合 join（快 3.3–3.5×）、JSON 序列化（快 4.4×）与解析（快 2.7×）、日期解析（快 4.6×）、事件发布（快 4.4× vs Guava）——来自零依赖手写实现 + 现代 JDK API，无框架层开销。
✅ vs Guava：join 持平、newArrayList 持平、contains 持平，事件发布快 4.4×；集合/字符串路径不落下风。
✅ dateFormat 已反转：v1.1.0 时代慢 5.6%（线程安全取舍）→ v1.19.0 快 2.1×，线程安全 + 性能兼得。
✅ 门禁全绿：16 项 sure/hutool 配对 ratio 全部 ≤ 1.5（最大 1.12），benchmark 门禁 PASS。

环境与复现

测量时间：2026-10-18 · 版本坐标：suretool v1.19.0（sure-core / sure-json / sure-benchmark）
环境：Linux VM x86_64 · JDK 25.0.12（Temurin）· -Xms256m -Xmx256m
框架：JMH（@Fork(1)，Warmup 3×1s，Measurement 5×1s，@BenchmarkMode(AverageTime)，单位 ns/op）
对照：hutool-core / hutool-json 5.8.x · guava 33.7.2-jre
复现：
  mvn -pl sure-benchmark -am package -DskipTests
  java -jar sure-benchmark/target/sure-benchmark-1.19.1-SNAPSHOT-jar-with-dependencies.jar
  python3 .github/scripts/benchmark_gate.py <log>   # 门禁判定（ratio ≤ 1.5）

局限：微基准反映热路径单次调用开销；真实应用请以 profiler（async-profiler/JFR）为准。
数据随 JDK/硬件变化，本报告仅代表上述环境。
