## 自动处理明细

- **HL-2026-10-15-01（三波修复，均自动完成）**：
  1. **第一波 `635bc1c`**：Windows FileTailer 全挂根因 = Windows/NTFS `fileKey()` 恒 null，原逻辑把 `key==null` 一律当"文件被删除"→ 永远 sleep 不读。修复为存在性 + size 回退检测；macOS WatchDir 测试断言放宽（PollingWatchService 合并 CREATE+MODIFY）。
  2. **第二波 `8026613`**：Windows 剩 FileTailer 轮转 3 例 + WatchDir 子目录 3 例。FileTailer 加 creationTime 联合检测（轮转=rename 后新建，创建时间必变）；WatchDir 平台线程 + pendingRegisters 延迟重试。
  3. **第三波 `bc099f7`（决定性）**：
     - **FileTailer 竞态根因**：start 同步打开旧 inode 后，若 tailLoop 首轮检测晚于 move+write，会把新文件 creationTime 记为基准而 channel 仍是旧 inode → 永不轮转、恒 EOF。修复：start() 同步取样 creationTime 基准 + 轮转重开后立即刷新 maxSize=channel.size() 与 creationTime；删除 channel.size() 首轮比对（并发追加窗口误判轮转重读历史）。新增 `forceNullFileKey` 包私有钩子模拟 Windows 分支 + `FileTailerWindowsBranchTest` 9 例 + `FileTailerRotateSoloTest` 1 例（本地连续 5 次全绿，修复前「start 后立即轮转」必现竞态）。
     - **WatchDir 子目录事件丢失根因**：Windows 上目录创建后注册可能延迟，注册窗口内写入的子目录内容事件丢失。修复：动态注册成功后 backfill 枚举补发 CREATE（含递归子目录）；filter 检查移到目录注册之后（否则子目录被过滤而漏监听）。新增 `WatchDirBackfillTest` 3 例。
     - **ubuntu jacoco 0.97 → 98.17%**：新增 Windows 分支代码此前在 Linux 未执行；forceNullFileKey 模拟测试补齐覆盖，行覆盖率 8481/8639=98.17%。
